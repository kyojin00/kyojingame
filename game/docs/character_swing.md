# 휘두르는 도트 그리기

도면: `docs/swing_guide.png` (`assets/ref/new_boy/make_swing_guide.js`가 만든다)

## 왜 도트가 필요한가

캐릭터는 **걷기 영상 15프레임을 도트로 변환**해 만든 것이다
(`assets/ref/new_boy/make_sprites.js`). 팔이 몸통 실루엣에 붙어 있어서,
코드로는 허리를 축으로 상체를 굽히고 도구 그림을 따로 얹는 데까지가 한계다
(`scripts/player.gd`). 「굽히기」는 그럴듯한데 「휘두르기」는 팔이 움직여야 한다.

방향 하나에 세 장만 있으면 그 방향이 바로 켜진다. 만드는 길은 둘이다 —
**원본에서 자동으로 뽑거나**(아래, 옆모습은 이미 이렇게 해 두었다),
도면 위에 손으로 그리거나.

## 무엇을 만드나

방향 하나에 **세 장**. 이름은 정확히 이래야 한다.

| 파일 | 자세 |
| --- | --- |
| `new_boy_<방향>_swing_0.png` | **다 감음** — 도구가 어깨 뒤로 넘어가고 몸이 젖혀진 순간 |
| `new_boy_<방향>_swing_1.png` | **중간** — 팔이 얼굴 옆을 지나 펴지는 순간 |
| `new_boy_<방향>_swing_2.png` | **다 내리침** — 도구가 발치에 닿고 허리가 굽은 순간 |

`<방향>` = `side` / `down` / `up`. 넣는 곳은 `assets/sprites/`.

**지금은 세 방향 다 도트가 없다.** 코드가 상체를 굽히고 도구 호를 그려
대신하고 있다. 도트를 넣으면 그 방향부터 켜진다.

- **옆모습은 오른쪽 보는 것만** 그린다. 왼쪽은 게임이 뒤집어 쓴다.
- **세 장이 다 있어야 그 방향이 켜진다.** 한 장만 넣으면 그 위상에서만
  도트가 되고 나머지는 서기 자세로 튀어 깜빡이므로, 게임이 아예 무시한다.
- 방향은 따로 켜진다. `side`만 만들고 앞뒤는 나중에 해도 섞인 채로 잘 돈다.
- 여자 캐릭터는 `player_f_<방향>_swing_0..2.png`. 규격은 똑같다.

## 도면 쓰는 법

`docs/swing_guide.png`는 **가로 3위상 x 세로 3방향**, 칸 하나가 정확히
128x192다. 쓸 칸을 그대로 오려 새 파일로 만들면 규격이 저절로 맞는다.
칸마다 서기 자세가 어둡게 깔려 있으니 **그 위에 팔만 고쳐 그리면 된다.**

| 표시 | 뜻 |
| --- | --- |
| 흰 선 (188행) | **발바닥.** 어긋나면 휘두를 때만 캐릭터가 뜨거나 파묻힌다 |
| 초록 점선 (136행) | **허리.** 게임이 여기서 상·하체를 갈라 상체만 돌린다 |
| 파랑 점선 (78행) | 어깨 — 팔이 시작하는 높이 |
| 회색 점선 (x=64) | **엉덩이 중심.** 어긋나면 휘두를 때 옆으로 순간이동한다 |
| 주황 십자 | **손잡이 끝이 와야 할 자리.** 주먹 한가운데를 여기 맞춘다 |
| 주황 점선 | 도구가 뻗는 방향 (날 끝까지) |
| 왼쪽 위 네모 | 위상 번호 (1개=`swing_0` / 2개=`swing_1` / 3개=`swing_2`) |

## 도구는 그리지 않는다

게임이 **손잡이 끝을 축으로 도구 그림을 따로 얹는다.** 도끼·곡괭이·호미·
물뿌리개가 이 도트 한 벌을 나눠 쓰기 때문이다 (도구까지 그리면 도구마다
따로 그려야 해서 4배가 된다). 도구를 그려 넣으면 **두 개가 겹친다.**

주황 십자에 **주먹만** 맞춰 두면 된다.

### 도구 아이콘의 방향 규칙

도구 그림(`icon_*.png`, 32x32)은 **자루가 왼쪽 아래, 머리가 오른쪽 위**로
누워 있어야 한다. 게임은 아래 한가운데(16,30)를 축으로 삼아 돌린다.

`icon_axe`·`icon_axe_stone`만 반대로 그려져 있어서(자루 오른쪽 아래 - 날
왼쪽 위), 오른쪽을 보고 휘두르면 **날이 등 뒤를 향했다.** 가방 아이콘은
그대로 둬야 하므로 휘두를 때만 뒤집는다 — `player.gd`의 `TOOL_MIRROR`.
새 도구 그림을 반대로 그렸다면 거기에 이름을 넣으면 된다.

## 규격

| | 값 |
| --- | --- |
| 캔버스 | 128 x 192 |
| 발바닥 | 188행 (내용은 3~189행 안에) |
| 엉덩이 중심 | x = 64 (내용은 24~110열 안에) |
| 색 | 서기 자세에서 **스포이드로만**. 전체가 정확히 28색이다 |

새 색을 쓰면 그 프레임만 색이 튄다. 그림자 한 단계가 더 필요하면 이미 있는
어두운 색을 쓰거나, `make_sprites.js`를 다시 돌려 팔레트를 통째로 다시 뽑는다.

## 세 자세

머리·몸통·다리는 서기 자세 그대로 두고 **팔만** 고친다. 상체를 조금 기울이는
정도까지. 실제로 손대는 픽셀은 전체의 15%쯤이다.

- **`swing_0` 다 감음** — 두 손이 머리 위~어깨 뒤. 가슴이 살짝 열리고 무게는 뒷발.
  여기가 예비동작이라 **제일 크게 젖혀야 한다.** 밋밋하면 「친다」로 안 보인다.
- **`swing_1` 중간** — 팔이 얼굴 옆까지 내려와 거의 펴진다. 두세 프레임만
  스치고 지나가므로 **대충 그려도 된다.** 오히려 흐릿한 편이 자연스럽다.
- **`swing_2` 다 내리침** — 팔이 아래로 쭉, 등이 앞으로 굽는다. 무게는 앞발.

**`side`부터 만들면 좋다.** 팔이 제일 잘 보여서 여기서 자세가 잡히면
앞뒤는 그걸 참고해 훨씬 빨리 된다.

## 넣고 확인하기

1. `game/assets/sprites/`에 파일 세 장을 넣는다 (등록·설정 없음)
2. Godot에서 F5 → 도끼를 들고 나무 앞에서 E

하네스로도 볼 수 있다:

```
KYOJIN_SHOT=/tmp/x/ godot --path game     ->  /tmp/x/_swing.png
```

## 코드가 알아서 해 주는 것

- `main._load_textures`가 `ResourceLoader.exists`로 **있으면 쓴다.**
  `TEXTURE_NAMES`에 넣으면 파일이 없을 때 터지므로 따로 챙긴다
- 도트가 켜지면 몸 굽히는 양이 `SWING_LEAN`(0.34) → `SWING_LEAN_DOT`(0.14)로
  준다. **자세를 도트에 세게 넣어도 겹쳐서 과해지지 않는다**
- 완급(예비동작·가속·히트스톱·되돌아오기), 무게 이동, 눌림, 도구 잔상은
  그대로 얹힌다 — 도트는 자세만 맡으면 된다

## 원본에서 자동으로 뽑기 (`make_swing_src.js`)

**만들어 봤지만 게임에는 안 넣었다.** 팔이 어색해서 뺐다 — 아래 「결론」 참고.
되살리려면 두 줄만 돌리면 된다.

원본(1280x720)에서 **팔을 지우고 새로 그린다.** 원본이 도트보다 3.5배 커서,
여기서 그리면 계단이 축소에 묻히고 팔레트도 알아서 맞춰진다.

```
cd game/assets/ref/new_boy
node make_swing_src.js      # 원본 3장 생성 + SWING_HAND_DOT 값 출력
node make_sprites.js        # 도트로 줄여 sprites/에 넣는다
```

### 왜 「지우고 그리기」인가

처음에는 팔을 **떼어 회전**시켰다. 이음매는 붙었지만 팔이 통짜 막대처럼
보였다 — 매달린 팔을 통째로 돌린 것이라 팔꿈치가 접히지 않고, 소매도
길게 늘어난 채 따라 돌기 때문이다.

이 도트는 평면 색 + 외곽선 구조라, 「굵기가 변하는 선분 + 둥근 끝」으로
팔을 그리면 원래 그림과 같은 결이 나온다. 대신 자세를 마음대로 잡을 수
있다 — 팔꿈치를 접고, 소매는 짧게 두고, 주먹은 제자리에 둥글게 놓는다.

### 지우는 쪽에서 걸린 것들

1. 아래팔·소매 안쪽에 씨앗을 놓고 **외곽선에 막힐 때까지 번진다.**
   팔과 몸통은 외곽선으로 갈라져 있어 여기서 저절로 끊긴다.
2. 팔이 챙겨 가는 외곽선은 3px만. 5px로 하면 반바지와 **나눠 쓰는**
   외곽선까지 떼어 가서 허리가 파인다.
3. 그래도 나눠 쓰던 외곽선의 바깥쪽이 몸에서 떨어져 **가느다란 검은 선**으로
   남는다. 몸 색에 안 붙은 어두운 점을 걷어낸다 — 단 **팔이 있던 자리
   안에서만**. 온 그림에 대고 돌리면 머리카락과 부츠처럼 원래 어두운
   덩어리가 통째로 갉인다 (실제로 그랬다).
4. **팔은 몸통 앞을 덮고 있다.** 그냥 지우면 그 뒤 몸통까지 없어져 상체가
   반쪽이 된다 (옆모습 셔츠 폭이 31px -> 15px). 지운 자리를 옆에 남은 몸
   색으로 **가로 방향으로** 메워 되살린다. 세로로 번지면 셔츠가 반바지로 샌다.
5. 지운 자리에 몸통 외곽선이 없어지므로, 「몸 색이 배경과 맞닿은 곳」에만
   새로 둘러 준다. 이미 어두운 곳은 안 건드려 원래 선이 안 두꺼워진다.

### 그리는 쪽에서 걸린 것들

- 색은 **팔레트(28색)에 실제로 있는 값**을 쓴다. 중간 색을 지어내면
  k-means가 새 칸을 잡아먹어 다른 색이 밀린다.
- 팔 외곽선은 원본보다 굵게(7px) 잡아야 3.5배 축소 뒤에 몸통 선과
  같은 굵기로 남는다.
- 굵기는 서기 그림에서 재 온다. 처음에 1.4배로 그렸더니 팔만 퉁퉁했다.

### 자세를 고치려면

`POSE`의 `[위팔 각, 아래팔 각]`만 만지면 된다. 0이 아래(차렷), 시계방향이 +.
**호가 머리 위를 지나게** 잡을 것 — 0을 지나가면 팔이 몸 옆으로 내려와
그냥 서기 자세로 보인다. 옆모습은 `[124,135] -> [-142,-69] -> [-41,-43]`이다.

### 방향을 늘리려면

`ARM`에 한 칸 더 넣으면 된다 — 어깨 자리, 팔 치수, 씨앗·`bound`, 세 자세의 각.
찍히는 `SWING_HAND_DOT` 값을 `player.gd`와 `make_swing_guide.js`에 옮긴다.

## 결론 — 이 방법의 한계

**서 있는 그림을 기하학적으로 바꿔서는 자연스러운 애니메이션이 안 나온다.**
두 가지를 다 해 봤다.

- **팔을 떼어 회전** — 팔꿈치가 안 접혀 통짜 막대로 보였다
- **팔을 새로 그리기** — 팔꿈치는 접히지만, 마디 굵기와 이음매가 손으로
  찍은 몸통과 결이 다르다. 자세를 아무리 맞춰도 팔만 붙여 넣은 티가 난다

자연스러운 동작은 프레임마다 **실루엣·무게·겹침**을 사람이 정해야 나온다.
서기 한 장에서 계산으로 만들어 낼 수 있는 것이 아니다.

그래서 만들어 둔 도트는 **게임에서 뺐다.** 어색한 팔을 보여주느니 팔을 안
건드리는 편이 낫다 — 지금은 코드가 상체를 굽히고 도구가 호를 그려 대신한다.

생성기(`make_swing_src.js`)와 도면은 남겨 뒀다. **진짜 휘두르는 프레임**이
생기면 그때 넣으면 되고, 자리는 이미 다 뚫려 있다.

되살려 보고 싶으면:

```
cd game/assets/ref/new_boy && node make_swing_src.js && node make_sprites.js
```

### 팔레트는 다시 계산된다

`make_sprites.js`는 18장 전체로 k-means를 다시 돌린다. 그래서 기존 15장도
아주 조금 바뀐다 — 재어 보니 한 장에 눈에 띄게 달라지는 점이 24576개 중
30~50개다. 색이 어긋나지 않게 하려는 것이므로 그대로 두면 된다.

크기 기준과 바닥선은 **걷기·서기 15장으로만** 잡으므로, 휘두르기 원본을
넣어도 이미 뽑아 둔 15장의 자리는 밀리지 않는다.

**다시 촬영하는 것은 권하지 않는다.** 같은 거리·조명이 아니면 휘두를 때만
캐릭터 크기가 변한다. 그렇게 되면 15장도 다시 찍어야 한다.
