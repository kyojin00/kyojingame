# 휘두르는 도트

주인공은 **앞·옆·뒤 모두 휘두르기 도트가 들어가 있다** — 네 벌
(`new_boy_*` 짧은 머리 · `hair_short_*` 단발 · `hair_spiky_*` 삐죽 · `player_f_*` 긴 머리)
전부. 지금 쓰는 그림(4판)은 **3세대 AI 시트 그림을 밑그림으로** 쓴다:
`assets/ref/ai_boy/make_sprites.py`가 `ai_boy/src/`의 30장(28색)을 픽셀마다
「무엇의 색인가」로 가려 **표준 팔레트 색으로 바꾸고**(그래야 게임이 옷·살결·
머리색을 갈아입힌다), 그 위에 머리 모양·깜빡임·속눈썹을 덧그린다.
방향마다 서기 1 + 걷기 5 + 휘두르기 5(시트 4장에서 「다 감음」을 둘로),
앞·옆은 눈 감은 한 장까지 벌당 35장이다.

```
cd game/assets/ref/ai_boy
python3 make_sprites.py     # -> assets/sprites/ 140장 + preview_*.png
```

갈색은 머리·바지·부츠가 다 같은 계열이라 색만으로 못 가른다 — 덩어리의
**자리**로 가른다(위 = 머리, 아래 = 부츠, 사이 = 바지). 눈은 검정 테에
갈색 홍채라 색으로는 앞머리 그늘과 구분이 안 돼, **서기 프레임에서 눈 상자를
손으로 읽어**(`EYE_BOXES`) 두고 다른 프레임은 머리 상자가 옮겨 간 만큼 같이
옮긴다.

살결이냐 옷이냐는 **덩어리째** 정한다. 부위마다 윤곽선이 둘려 있어, 윤곽선을
넘지 않고 이어진 칸을 모으면 얼굴·소매·손·다리·셔츠가 저절로 나뉜다. 덩어리
안에서 살결 바탕색(분홍)과 옷 바탕색(크림)을 세어 많은 쪽으로 통째로 정하고,
목에서 얼굴과 셔츠가 붙어 버린 덩어리만 안에서 다시 가른다. 칸마다 이웃
다수결로 정하던 때는 옷단·소매 끝에서 뒤집혀 **얼굴에 파란 점, 셔츠에 살구색
얼룩**이 흩뿌려졌다.

그리고 나서 **손도트 정리**를 한다 — 홀로 뜬 점 지우기(이웃 여덟 중 다섯이
한 색이면 그 색으로), 면 안에 낀 검은 티끌 빼기, 실루엣에 뚫린 윤곽선 메우기.
눈·입은 두 칸짜리라 티끌로 몰려 지워지므로 건드리지 않는다.

여자(`player_f_*`)는 **머리부터 다시 그린다.** 남자 그림에 머리만 얹으면
같은 사람이 가발을 쓴 것으로 보인다 — 골격(자세·팔다리 자리)만 가져오고
사람은 새로 그린다. 모티브는 `assets/ref/f3_front.png` 의 소녀다.

* **머리** — 삐죽한 더벅머리를 깎아(5x5 안에 머리카락이 열셋 미만인 칸을
  네 번 벗겨 낸다) 머리통에 붙는 둥근 단발로 만들고, 귀 옆 머리채와
  옆으로 묶은 한 다발, 정수리 안테나를 **머리통 가장자리에 붙여** 얹는다
  (머리 상자 끝에 맞춰 놨더니 둥근 머리통에서 떨어져 막대가 떠 있었다)
* **윗도리** — 가슴 가운데를 조끼(어두운 칸)로, 소매·깃을 블라우스(밝은 칸)로.
  조끼만 한 단 어둡게 칠했더니 같은 파랑 안에서 「좀 짙은 셔츠」로 보여서,
  소매를 한 단 올려 두 겹으로 읽히게 했다
* **아래** — 반바지 자리에 허리에서 부챗살처럼 퍼지는 짧은 주름치마.
  밑단은 주름 끝마다 한 칸씩 오르내린다. 색은 바지 칸을 그대로 쓰므로
  생성창의 「바지」 색이 치마 색이 된다

코드가 도트를 직접 그린 2·3판(`dot_boy/`)은 눈매를 아무리 고쳐도
「못생겼다」「이상하다」는 말을 벗지 못해 접었다. 생성기는 남겨 두었다.

아래 「시트를 새로 뽑는다면」부터는 **3세대(AI 시트)** 시절의 기록이다 —
`new_boy3/make_sprites.js`를 다시 돌리면 지금 그림을 덮어쓰니 돌리지 말 것.

## 무엇이 만들어지나

| 파일 | 자세 |
| --- | --- |
| `new_boy_<방향>_walk_0..4` | 걷기 5장 |
| `new_boy_<방향>_idle` | 서기 |
| `new_boy_<방향>_swing_0` | **감기 시작** — 주먹이 가슴~어깨께로 올라온다 |
| `new_boy_<방향>_swing_1` | **다 감음** — 팔이 머리 위로 곧게 선다 |
| `new_boy_<방향>_swing_2` | **내리침** — 등이 굽고 주먹이 발치에 닿는다 |
| `new_boy_<방향>_swing_3` | **되돌아옴** — 다시 서면서 주먹이 앞에 남는다 |

`<방향>` = `side` / `down` / `up`. **옆모습은 오른쪽 보는 것만** 만든다 —
왼쪽은 게임이 뒤집어 쓴다.

- **네 장이 다 있어야 그 방향이 켜진다.** 한 장만 넣으면 그 위상에서만
  도트가 되고 나머지는 서기 자세로 튀어 깜빡이므로, 게임이 아예 무시한다
  (`player.gd`의 `_swing_frame`).
- 방향은 따로 켜진다. `side`만 있어도 앞뒤는 코드가 대신하며 섞인 채로 돈다.
- 여자 캐릭터는 `player_f_<방향>_swing_0..3.png`. 규격은 똑같다.

## 도구는 그리지 않는다

게임이 **쥐는 자리를 축으로 도구 그림을 따로 얹는다.** 도끼·곡괭이·호미·
물뿌리개가 이 도트 한 벌을 나눠 쓰기 때문이다 (도구까지 그리면 도구마다
따로 그려야 해서 4배가 된다). 도구를 그려 넣으면 **두 개가 겹친다.**
손은 **빈 주먹**으로 두면 된다.

### 주먹 자리를 코드에 옮겨 적어야 한다

도구가 어디에 얹힐지는 `player.gd`의 `SWING_HAND_DOT`에 손으로 적혀 있다.
**그림을 다시 뽑으면 이 값도 다시 읽어야 한다** — 안 맞으면 도구가 손에서
뜬다. 읽는 법:

1. `preview_<방향>_swing.png`를 연다 (10칸마다 눈금, 50칸마다 밝은 눈금.
   원점은 발밑 가운데, 위가 음수)
2. 위상마다 주먹 한가운데 좌표를 읽는다
3. `node.x = 도트.x / 2`, `node.y = (도트.y + 2) / 2` 로 바꿔 적는다
   (스프라이트를 0.5배로, offset `-64,-188`로 그린다)

### 도구 아이콘의 방향 규칙

도구 그림(`icon_*.png`, 32x32)은 **자루가 아래, 머리가 위**로 누워 있어야
한다. 자루 끝이 그림 어디에 있는지는 도구마다 다르므로 `player.gd`의
`TOOL_GRIP`에 **아이콘 안 픽셀 좌표**로 적어 둔다. 새 도구를 넣으면 여기에도
한 줄 넣어야 한다 — 안 넣으면 한가운데 아래(16,30)를 잡아 자루가 모서리에
있는 도구는 손에서 10px 넘게 뜬다.

`icon_axe`·`icon_axe_stone`만 자루가 **오른쪽 아래**(나머지는 왼쪽 아래)라,
그대로 두면 오른쪽을 보고 휘두를 때 날이 등 뒤를 향한다. 가방 아이콘은
그대로 둬야 하므로 휘두를 때만 뒤집는다 — `TOOL_MIRROR`.

## 규격

| | 값 |
| --- | --- |
| 캔버스 | 128 x 192 |
| 발바닥 | 190행 |
| 좌우 기준 | x = 64 (내용은 0~127 안에) |
| 키 | 184px 안팎 (AI 시트는 `HEAD_H`로 맞췄다) |
| 색 | 30장 전체가 정확히 28색 |

## 시트를 새로 뽑는다면

`make_sprites.js`가 시트 한 장에서 자르기까지 다 한다. 시트가 지켜야 할 것:

- **6줄 x 5칸**, 초록 배경. 줄 순서는 옆걷기 · 앞걷기 · 뒤걷기 ·
  옆휘두르기 · 앞휘두르기 · 뒤휘두르기
- 휘두르기 줄의 다섯 칸 = 서기 · 감기 시작 · 다 감음 · 내리침 · 되돌아옴
- **같은 인물·같은 색·같은 크기.** 걷기와 휘두르기의 크기가 다르면 칠 때마다
  캐릭터가 커지거나 작아진다 (2세대 시트가 그랬다 — 서기만 12% 컸다)

돌린 뒤 로그를 본다:

```
frames 30  scale 0.8896  palette 28  불똥 등 떼어 낸 픽셀 1388 + 도트 티끌 8
키 최대 186 px (캔버스 192) · 중심에서 좌우 최대 64 px (반폭 64)
```

- **키가 192에 가까우면** `HEAD_H`를 낮춘다 (머리 비율이 세대마다 다르다)
- **좌우가 64를 넘으면** 그 칸은 캔버스 밖으로 나간 만큼 저절로 밀린다.
  어느 칸이 밀렸는지도 같이 찍힌다

### 스크립트가 알아서 해 주는 것

- **초록 번짐 지우기** — 테두리에 얹힌 초록을 누른다. 안 하면 도트에
  초록 실선이 남는다
- **불똥 떼기** — 내리치는 칸에 그려진 노란 불똥을 지운다. 게임이 맞는 순간
  제 파티클을 뿌리므로 그림에 있으면 두 번 튀고, 발치에서 옆으로 뻗어
  스프라이트 폭까지 잡아먹는다
- **바닥선 맞추기** — 줄마다 발이 같은 자리에 오게 한다
- **좌우 기준** — 걷기는 허리, 휘두르기는 **밟고 선 자리의 무게중심**.
  팔을 뻗거나 몸을 굽힌 칸은 허리 띠가 팔다리를 같이 집어서 못 쓴다
- **팔레트** — 30장을 한 번에 k-means로 28색까지 줄인다

## 코드가 알아서 해 주는 것

- `main._load_textures`가 `ResourceLoader.exists`로 **있으면 쓴다.**
  `TEXTURE_NAMES`에 넣으면 파일이 없을 때 터지므로 따로 챙긴다
- 도트가 켜지면 **몸을 가르지 않는다.** 그림이 이미 굽힌 자세라 상체 회전을
  또 얹으면 두 번 굽고, 자른 자리가 그림의 팔을 가로지른다
- 완급(예비동작 · 가속 · 히트스톱 · 되돌아오기), 무게 이동, 눌림, 도구 잔상은
  그대로 얹힌다 — 도트는 자세만 맡으면 된다
- 위상은 **시간**으로 가른다. 내리친 그림은 판정 순간부터 남은 시간의 절반
  넘게 붙들어 둔다. 히트스톱만큼만 보이면 제일 중요한 자세가 두 프레임 만에
  지나가 눈에 안 남는다

## 확인하기

```
KYOJIN_SHOT=/tmp/x/ godot --path game
```

- `_swing_p0..p3.png` — 네 위상을 한 장씩. **도구가 주먹에 붙어 있는지**는
  수치로 안 보이므로 이걸 봐야 한다
- `SWING_PHASE_OK` — 위상이 0->1->2->3으로 한 번씩만 지나는가
- `SWING_SPLIT_OK` — 도트와 몸 가르기 중 **하나만** 쓰는가
- `SWING_TIMING_OK` — 내리치는 정점이 `HIT_AT`에 정확히 오는가

## 지난 세대

| | 원본 | 결과 |
| --- | --- | --- |
| `new_boy/` | 걷기 영상 15프레임 | 걷기만. 휘두르기는 **팔을 지우고 새로 그려** 봤지만 어색해서 뺐다 |
| `new_boy2/` | AI 시트 (걷기 5 + 서기) | 걷기·서기. 휘두르기 없음 |
| `new_boy3/` | AI 시트 (걷기 5 + 휘두르기 5) | 3세대. 얼굴은 좋았지만 마을 사람과 도트 굵기가 달라 뺐다 |
| `dot_boy/` | 없음 — 코드가 그린다 | 2·3판. 도트가 굵거나(2판) 뻣뻣해서(3판) 접었다 |
| `ai_boy/` | 3세대 시트 결과물 30장 | **지금 쓰는 것.** 팔레트로 분류 + 머리 모양 덧그림, 네 벌 x 35장 |

`new_boy/make_swing_src.js`는 **서 있는 그림을 기하학적으로 바꿔** 휘두르는
자세를 만들어 보려던 것이다. 팔을 떼어 돌리면 팔꿈치가 안 접혀 통짜 막대가
되고, 팔을 새로 그리면 마디 굵기와 이음매가 손으로 찍은 몸통과 결이 달라
붙여 넣은 티가 난다. **자연스러운 동작은 프레임마다 실루엣·무게·겹침을
사람(또는 영상)이 정해야 나온다** — 서기 한 장에서 계산으로 만들 수 없다.
그래서 3세대는 휘두르는 자세까지 **그려진 것을 받아** 쓴다.
