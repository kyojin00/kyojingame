# 대화키를 F로 — 캐다가 말이 걸리지 않게

관련 코드: `project.godot`(input) · `interact.gd`(`talk()`/`interact()`) ·
`main.gd`(`_unhandled_input`) · `renderer.gd`(머리 위 안내) ·
`dialog_ui.gd` · `game_data.gd`(BINDABLE_ACTIONS) ·
`dev_harness.gd` 스텝 236(`TALKKEY_OK`)

---

## 왜 갈랐나

예전에는 **E 하나가 캐기와 말 걸기를 겸했다**. 그래서 나무를 연타하다
옆에 사람이 서 있으면 도끼질이 대화로 새 버렸다. 그것을 막으려고
`interact()` 안에 방어 코드가 겹겹이 쌓여 있었다 —

* `aiming_object`: 나무·돌·채집물을 조준 중이면 대화를 건너뛴다
* `_work_lock`: 마지막 한 방에 나무가 부서져도 0.6초 동안은 무조건 도구다

앞의 것은 이제 필요 없다. **키가 다르면 샐 길이 없다.**

## 무엇이 어느 키인가

| 키 | 액션 | 하는 일 |
|----|------|---------|
| **F** | `talk` | 사람에게 말 걸기 · 가축 쓰다듬기 · 우체부 아저씨 |
| **F** | `mount` | 앞에 아무도 없을 때 — 말 타기 / 내리기 |
| **E** | `interact` | 벌목 · 채광 · 채집 · 곤충 · 문 · 계산대 · 표지판 · 밭일 |

F가 두 액션에 걸려 있는 것은 일부러다. `main._unhandled_input`이
**말 걸기를 먼저 시도하고**, `actions.talk()`이 `false`(주위에 사람도
가축도 없다)를 돌려줄 때만 말 타기로 넘긴다. 사람 옆에서 F를 눌렀는데
말에 올라타는 일도, 말 옆에서 F를 눌렀는데 아무 일도 안 일어나는 일도
없다.

말 위에서는 `talk()`이 언제나 `false`라, F가 그대로 「내리기」가 된다.

## 어떻게 알려 주나

키 이름을 문장에 박아 두지 않는다. 전부 `GameData.key_label("talk")`을
거치므로, 설정에서 키를 바꾸면 안내도 같이 바뀐다.

* 사람·가축 곁에 서면 머리 위에 `F: 대화` / `F: 쓰다듬기`
* 우체부 첫 만남 안내 — 「가까이 가서 F를 눌러보자」
* 설정 화면 키 목록에 `대화 (사람·가축)` 한 줄이 새로 생겼다

대화창은 F·E·Space 셋 다로 넘길 수 있다. 말을 걸 때 누른 키로 그대로
읽어 내려갈 수 있어야 하기 때문이다.

## 마우스는 그대로

더블클릭은 예전처럼 「알아서」 한다 — 물건이면 E의 일, 사람·가축이면
F의 일, 빈 칸이면 손에 든 도구.

## 검사 (스텝 236)

1. **키배치** — `talk`에 F, `interact`에 E가 실제로 걸려 있다
2. **F로대화** — 도끼를 든 채 사람 앞에서 `talk()` → 대화창이 뜬다
   (예전이라면 조준 때문에 막혔을 자리다)
3. **E는조용** — 같은 자리에서 `interact()` → 대화창이 뜨지 않는다
4. **아무도없을때** — 주위에 사람이 없으면 `talk()`이 `false`를 돌려준다
   (그래야 같은 F가 말 타기로 넘어간다)
