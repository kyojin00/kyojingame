# 성능

## 재는 법

추측하지 않는다. 하네스가 매번 숫자를 뱉는다 (`dev_harness.gd`의 387·389단계):

```
PERF: 드로우콜=195 노드=2271 world자식=709 오브젝트=911 _process=122us
PERF_BREAKDOWN: story=1 fade=7 treefade=7 mouse=2 particles=0 nightmobs=4 hud=140 growth=283 hitfx=2
PERF_DRAWCALLS_OK=true 콜=195
PERF_PROCESS_OK=true us=122
```

`PERF_BREAKDOWN`은 매 프레임 도는 것들을 하나씩 20번 불러 평균을 낸 값(µs)이다.
**어디가 무거운지 여기서 먼저 보고 손댄다.**

주의: 검증 환경은 소프트웨어 렌더러(llvmpipe)라 **FPS는 뜻이 없다.**
믿을 수 있는 건 드로우콜 수(기계와 무관)와 GDScript 처리 시간이다.

## 손본 것 네 가지

손보기 전 → 후. `_process` **953µs → 122µs**, 드로우콜 **813 → 195**.

### 1. 지형을 텍스처별로 모아 그린다 (813 → 195 드로우콜)

칸 순서대로 그리면 잔디 → 물 → 길 → 잔디로 텍스처가 계속 바뀌어 배치(batch)가
매번 끊긴다. 보이는 칸이 38 x 22쯤이니 **칸 수만큼 드로우콜이 났다.**

`_draw()`가 이제 한 번 훑으면서 텍스처별로 자리를 모아 두었다가, 같은 텍스처끼리
붙여 그린다. 겹치는 순서는 지킨다 — 바탕 → 부두 → 길 가장자리 → 작물.
바탕끼리는 한 칸에 하나뿐이라 순서를 바꿔도 안전하다.

### 2. HUD를 초당 열 번만 다시 짠다 (732µs → 실질 14µs)

두 가지가 겹쳐 있었다.

- 핫바 12칸에 **매 프레임** 스타일박스를 새로 씌우고 있었다. 그때마다
  Control이 다시 배치된다. 지금은 (선택 도구 + 슬롯 구성 + 해금 상태)로
  서명을 만들어, 바뀌었을 때만 다시 그린다.
- `Label.text`에 같은 글을 다시 대입하면 글자 배치를 새로 계산한다. 한글은
  이 비용이 특히 크다. `_put()`이 같으면 건너뛴다.

그래도 「무슨 글을 넣을지」 만드는 비용(목표·의뢰·축제 줄 이어 붙이기)이
프레임당 0.12ms 남아서, 전체를 **0.1초에 한 번**으로 줄였다. 시계는 게임 분
단위라 눈에 안 보인다. 체력 막대만 매 프레임 따라간다.

명시적으로 부를 때는 `hud.refresh(true)`로 지연 없이 갱신한다.

### 3. 「돌아가고 있는 칸」만 돈다 (4132µs → 283µs)

`_growth_tick`이 0.7초마다 지도 전체 **10,800칸**을 훑었다. 실제로 자라거나
마르는 칸은 늘 몇십 개뿐인데. 0.7초마다 4ms짜리 끊김이 걸렸다.

`farming._ticking`이 그 칸들만 담는다. 젖거나 심긴 순간에 들어오고
(`farming.touch`), 마르고 작물도 없으면 빠진다. **칸 Dictionary를 그대로
담는다** — 성장 계산에 좌표가 필요 없기 때문에 위치를 넘길 필요가 없었다.

세계가 통째로 바뀌는 자리에서는 다시 만든다 (`farming.rebuild`):
맵 생성 · 세이브 펴기 · 통신 동기화 · **하루 넘김**. 마지막 것이 그물이다 —
어딘가에서 `touch`를 빠뜨려도 하루 안에 저절로 맞춰진다.

### 4. 마우스 위치를 매 프레임 묻지 않는다 (148µs → 2µs)

`get_global_mouse_position()`은 창 시스템에 물어본다. 매 프레임 도는 것 중
제일 비쌌다. 지금은 마우스가 **움직일 때만** 화면 좌표를 적어 두고
(`main._unhandled_input` → `actions.mouse_screen`), 화면 → 월드 변환만
매 프레임 한다. 변환은 싸다.

## 아직 남은 것

- **드로우콜 195 중 대부분은 월드 스프라이트다.** 709개가 y 정렬로 섞여
  그려지니 같은 나무 텍스처끼리도 배치가 끊긴다. 텍스처 아틀라스로 묶으면
  더 줄겠지만, 스프라이트를 전부 다시 뽑아야 해서 지금 할 일은 아니다.
- `hud`가 여전히 한 번에 0.14ms다 (초당 열 번이라 실질 14µs). 더 줄이려면
  목표·의뢰 줄을 상태가 바뀔 때만 다시 만들어야 한다.
