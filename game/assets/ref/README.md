# 참조용 원본 (게임이 읽지 않는다)

여기 있는 그림은 **스프라이트를 뽑아 내는 재료**다. 게임은 결과물
(`assets/sprites/`)만 읽는다.

`.gdignore`가 있어서 **Godot이 이 폴더를 통째로 건너뛴다.** 62MB를 매번
들여오지 않으니 첫 실행이 빨라지고, `.godot` 캐시와 내보낸 빌드에도 안 들어간다.
대신 여기 파일은 `res://`로 못 읽는다 — 생성기 스크립트가 node로 직접 읽으므로
상관없다.

| 폴더 | 원본 | 만드는 것 |
| --- | --- | --- |
| `new_boy3/` | AI 시트 (걷기 5 + 휘두르기 5) x 3방향 | **지금 쓰는 남자 캐릭터** 30장 |
| `new_boy2/` | AI 시트 (걷기 5 + 서기) | 옛 걷기·서기 — 안 쓴다 |
| `new_boy/` | 걷기 영상 15프레임 | 1세대. 휘두르기 도면 생성기가 여기 있다 |
| `npc/` | NPC 원본 | 마을 사람 도트 |
| `trees/` `mat/` `src/` | 지형·오브젝트 원본 | 타일·나무·바위·아이템 |

**1·2세대 생성기는 돌리지 말 것.** `new_boy3`와 같은 이름으로 덮어써서
걷기만 옛 그림으로 바뀐다 (칠 때 캐릭터 머리 크기가 달라진다).

## 바닥 — `make_ground.js`

`node make_ground.js` 는 `proposed_*.png` 로만 뽑고, `--install` 을 붙여야
`sprites/` 에 들어간다. 돌릴 때마다 지난 제안본을 먼저 지운다 — 안 그러면
미리보기가 옛 그림을 집어 쓴다.

**경계는 방향이 아니라 이웃 아홉 칸의 꼴로 그린다.** 여덟 이웃 중 어디가
딴 쪽인지를 비트로 모으면(1=북 2=남 4=서 8=동 16=북서 32=북동 64=남서
128=남동) 256가지가 나오고, 그 값이 곧 아틀라스의 칸 번호다 (0번은 빈칸).

넷만 봐서는 안 된다 — 볼록한 귀퉁이에서 땅 칸은 제 모서리를 깎아 물을
들이는데 옆 물 칸은 물가가 아직 타일 변에 있는 줄 알아서, 같은 자리를
둘이 다르게 그려 여울 띠가 모서리마다 어긋났다. 아홉 칸을 보면 이웃한
두 칸이 겹치는 창을 보므로 경계를 똑같이 잰다.

모양은 식이 아니라 **재서** 얻는다. 창을 덮개(0/1)로 깔고 뭉갠 뒤 0.5에서
자르면 볼록·오목이 한꺼번에 둥글려지고, 거기서 부호 거리를 재면 한 점마다
둘이 나온다 — 경계에서 들어간 **거리 s**, 딴 쪽을 가리키는 **방향 n**.
층은 s로 쌓고 벽이 보이는지는 n으로 정한다. 곧은 변·귀퉁이·곶·섬·물목이
전부 같은 자로 그려져 예외가 없다.

| 아틀라스 | 얹는 칸 | 무엇 |
| --- | --- | --- |
| `edge_shore` / `edge_shoal` | 뭍 / 물 | 연못·강. 둑이 서고 남쪽을 보는 면에만 돌벽 |
| `edge_beach` / `edge_surf` | 모래 / 물 | 바다. 벽 없이 모래가 기울어 들고 거품이 민다 |
| `edge_dune` / `edge_trod` | 잔디 | 모래·마당 흙이 풀밭으로 흘러든다 |

한 칸은 **한 도트에 1픽셀**(16x16)이다 — 화면에서 어차피 두 배로 늘려
그리므로(필터 nearest) 4배로 부풀린 것과 결과가 같고, 256칸이 한 장에 든다.

`water_<깊이 0~7>_<판 0~2>_<장 0~1>` — 깊이는 뭍에서 몇 걸음인지(main.gd의
`rebuild_water_levels`)로 고른다. 한 단이 0.42톤이라 계단이 안 보인다.
**판**은 한 장을 호수에 반복해 깔 때 잔물결이 같은 자리마다 찍혀 바둑판이
뜨는 걸 막는다 — 잔디·모래·길·마당도 같은 이유로 셋씩이다.
